# EdgeEnv v0.1.3 Post-release Sanity Sweep

> Language: [English overview](language.md#english-overview) | [한국어/원문](#)

## 1. WHAT — 이 문서가 정하는 것

`v0.1.3` tag와 GitHub Release 생성 후, 외부 사용자가 처음 보는 문서 경로에 오래된 release 표현이나 범위 오해가 남아 있는지 확인한 기록이다.

이 문서는 새 기능 설계가 아니다. README 첫 화면, `v0.1.3` follow-up note, GitHub Release 본문, release maintenance 문서의 사용자-facing 문구만 가볍게 점검한다.

## 2. CONTENTS — 확인 대상

Checked files and surfaces:

- `README.md` — first screen and Guide Map
- `docs/release-follow-up-v0.1.3.md` — current release starting point
- `docs/release-maintenance-checklist.md` — release gate pointer
- GitHub Release `v0.1.3` — published release body

## 3. HOW — 점검 결과

Status: passed with small README/follow-up cleanup.

Observed:

- README first screen says `Start Here for v0.1.3`.
- `edgeenv doctor` reports `Version: 0.1.3`.
- GitHub Release title is `EdgeEnv v0.1.3`.
- GitHub Release body keeps the release framed as first-user polish.
- GitHub Release non-goals exclude OS, VM, Docker, WSL, SSH, cloud, auth, dashboard, leaderboard, upload server, and composite ranking.
- Resource metrics remain described as supplemental lookup evidence, not a comparability gate.

Cleanup applied:

- README Guide Map now puts the `v0.1.3` follow-up note first.
- Older `v0.1.2` follow-up and release planning documents were moved out of the first-start path into a release/maintenance grouping.
- `docs/release-follow-up-v0.1.3.md` now links directly to the published GitHub Release.

## 4. HOW NOT — 피해야 할 함정

- Do not remove historical `v0.1.2` docs; they remain useful release history.
- Do not make `v0.1.3` sound like a new target/runtime release.
- Do not describe Jetson validation as SSH or remote target support.
- Do not imply resource metrics are used for ranking or comparability gates.

## 6. WHY — 배경 판단

Release 직후에는 기능보다 신뢰 경로가 중요하다. 사용자가 첫 화면에서 “현재 버전이 무엇인지”, “어디서 시작해야 하는지”, “무엇을 지원하지 않는지”를 바로 이해해야 한다.

`v0.1.3`은 first-user polish release이므로, 이전 버전 기록은 보존하되 첫 진입 경로에서는 현재 release를 먼저 보여준다.

## 7. ⚠️ LEARNED CAUTIONS — 학습된 주의사항

- Post-release sanity sweep은 오래된 문서를 삭제하는 작업이 아니라, 현재 release 시작 경로와 historical reference를 분리하는 작업이다.
