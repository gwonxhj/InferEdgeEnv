# EdgeEnv v0.1.3 User Feedback Backlog

> Language: [English overview](language.md#english-overview) | [한국어/원문](#)

## 1. WHAT — 이 문서가 정하는 것

`v0.1.3` 이후 새 기능을 바로 추가하기 전에, 외부 사용자가 README 시작 경로를 따라가며 어디서 막히는지 수집하는 기준이다.

이 문서는 feature roadmap이 아니다. README Quickstart, local command 연결, compare 판단, optional Jetson 문서 흐름에서 나온 질문을 같은 형식으로 모아 다음 작은 개선 후보를 고르는 backlog다.

## 2. CONTENTS — 수집할 질문

Collect feedback about:

- install or entrypoint confusion
- fake run command failures
- local command contract questions
- missing or unclear example config paths
- `report compare` interpretation questions
- resource metrics lookup confusion
- Jetson setup or repeated measurement friction
- export/import or bundle handoff questions

Do not collect requests for unsupported scope here:

- remote SSH runner implementation
- Docker, WSL, VM, cloud execution
- dashboard, leaderboard, login/auth
- model or dataset upload service
- composite score or ranking

## 3. HOW — 수집 방식

Preferred intake:

1. Ask the user to start from README's `Start Here for v0.1.3` path.
2. Ask for the first command or document section that was confusing.
3. Ask whether the issue blocked progress or only slowed interpretation.
4. Capture the exact command, output, OS/Python version, and whether the run used fake, local, or Jetson-local execution.
5. Label the issue by the first blocked path: `install`, `fake-run`, `local-command`, `compare`, `resource-query`, `jetson-docs`, or `export-import`.

Use the GitHub issue template:

- [README Quickstart Feedback issue](https://github.com/gwonxhj/InferEdgeEnv/issues/new?template=readme-quickstart-feedback.md)
- [Template source](../.github/ISSUE_TEMPLATE/readme-quickstart-feedback.md)
- [Feedback Template Rehearsal](v0.1.3-feedback-template-rehearsal.md)

## 4. HOW NOT — 피해야 할 함정

- Do not treat every question as a feature request.
- Do not expand MVP scope just because a user asks for remote execution.
- Do not change result schema, `metadata.json`, `result.json`, or compare output while triaging wording feedback.
- Do not make resource metrics part of comparability or ranking.
- Do not rewrite old release documents unless they actively mislead the current first-start path.

## 5. WHERE — 정리 위치

Use these locations:

- README first screen: only the shortest feedback pointer
- `docs/release-follow-up-v0.1.3.md`: current release trust path and feedback intake pointer
- GitHub Issues: one issue per blocked user path
- Future polish branch: only after repeated feedback points to the same friction

## 6. WHY — 배경 판단

`v0.1.3` already tightened install, quickstart, resource query output, and release maintenance flow. The next best signal is not another feature; it is whether a new user can move from README to a fake run, local command run, compare report, and optional Jetson-local evidence without hidden assumptions.

Feedback should preserve EdgeEnv's product boundary: local run evidence registry, artifact portability, and comparability judgement.

## 7. ⚠️ LEARNED CAUTIONS — 학습된 주의사항

- User feedback after a polish release should identify the first blocked path before proposing new implementation work.
