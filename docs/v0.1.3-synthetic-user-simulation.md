## 1. WHAT — 이 문서가 정하는 것

실제 외부 사용자가 당장 없을 때, README 시작 경로를 역할별로 읽어 보며 막힘 후보를 찾는 기준과 이번 점검 결과를 기록한다.

이 문서는 feature roadmap이 아니다. 새 기능을 상상해 추가하지 않고, 이미 문서화된 `v0.1.3` 경로가 사용자 역할별로 자연스럽게 이어지는지 확인한다.

## 2. CONTENTS — 시뮬레이션한 사용자

Personas:

- First-run evaluator: README만 보고 설치, `doctor`, fake run까지 확인하려는 사용자
- Local adapter builder: 자기 benchmark command를 `target_type: local`에 붙이려는 사용자
- Jetson operator: Jetson shell에서 sampled evidence를 반복 실행하고 보관하려는 사용자
- Evidence reviewer: exported bundle, compare output, bundle summary를 받아 해석하려는 사용자

Documents reviewed:

- `README.md`
- `docs/v0.1.3-feedback-template-rehearsal.md`
- `docs/local-command-contract.md`
- `docs/compare-workflow-guide.md`
- `docs/jetson-operations-checklist.md`
- `.github/ISSUE_TEMPLATE/readme-quickstart-feedback.md`

## 3. HOW — 결과

### First-run evaluator

Status: clear after the `run_id` handoff wording.

The README now tells users to use the `Run ID` printed by `bench run` or copied from `edgeenv runs list` before calling `runs show <run_id>`.

No additional change needed.

### Local adapter builder

Status: clear.

`docs/local-command-contract.md` gives the required stdout contract, primary metrics fields, optional resource metrics behavior, config checklist, and troubleshooting table. It also explains that `warmup_runs` and `repeat_runs` are protocol fields the command itself should honor, not subprocess loop controls.

No additional change needed.

### Jetson operator

Status: small wording drift found and fixed.

The README points users to Jetson measurement operations from the current `v0.1.3` entry path, but `docs/jetson-operations-checklist.md` still framed the operational baseline as `v0.1.2`. That can make a user wonder whether the checklist is stale.

Cleanup applied:

- Updated the Jetson operations checklist current baseline references from `v0.1.2` to `v0.1.3`.
- Updated the archive filename examples to `inferedgeenv-v0.1.3-ops.tar`.
- Preserved the historical `Validation Record — nano01` that explicitly records a past `v0.1.2` run.

### Evidence reviewer

Status: clear.

`docs/compare-workflow-guide.md` explains that `Metrics Delta` appears only for `Comparable: Yes` and `Mode: same-condition`. It also points to Jetson sampled comparison, conditional comparison, target comparison, and evidence bundle handoff records.

No additional change needed.

## 4. HOW NOT — 피해야 할 함정

- Do not invent feedback that implies a new feature is already needed.
- Do not rewrite historical validation records just because the current release changed.
- Do not make Jetson docs sound like remote SSH runner support.
- Do not collapse compare/resource/sampler evidence into ranking language.

## 6. WHY — 배경 판단

Actual user feedback is best, but synthetic user simulation is useful when it is constrained. The point is not to guess features; it is to catch mismatched wording, stale release references, and missing handoff hints before they become real support friction.

The strongest signal remains repeated real feedback. Synthetic findings should stay small and documentation-focused unless they reproduce a real command failure.
