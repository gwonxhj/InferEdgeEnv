## 6. WHY — 배경 판단

`v0.1.3` 후보 1~4는 first-user polish 작업이었다. 이번 리허설은 새 기능을 더하지 않고, 그 polish가 실제 사용자 흐름에서 닫히는지 확인했다.

현재 결과는 release maintenance checklist의 필수 local gate를 통과한다. 다만 tag와 GitHub Release는 별도 release branch에서 version bump와 함께 수행하는 편이 안전하다.

## 7. ⚠️ LEARNED CAUTIONS — 학습된 주의사항

- Release rehearsal PR은 tag/release PR과 분리한다. 리허설 문서가 merge되고 CI가 통과한 뒤에 version bump/tag/GitHub Release로 넘어간다.
